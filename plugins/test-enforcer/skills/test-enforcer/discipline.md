# 测试纪律手册（discipline.md）——test-writer 的强制规范

> 本手册是硬约束，不是建议。每条都是 P5 契约的强制项。你的产出会被独立验证器
> （假测试 AST 扫描）和变异测试对抗性检验——写得敷衍会被机器抓住。

## 第 0 步：要点分析（先于任何测试代码）

对每个被测单元（函数/类/模块），先列出并展示：

1. **输入域等价类**：每个参数的有效类/无效类
2. **边界值点**：0、-1、max、min、空集合、None/null、NaN、空串（视类型适用）
3. **错误传播路径**：哪些内部失败会以什么形式传出（异常类型/错误码/返回值）
4. **状态转移**（有状态单元）：全部状态×触发事件×迁移×副作用

未完成要点分析就开始写测试 = 违纪。

## L1 单元测试（每个公共函数强制三类）

| 类别 | 要求 |
|---|---|
| Happy path | 每个等价类至少 1 例 |
| 边界值 | 要点分析列出的每个边界点至少 1 例 |
| 异常路径 | 每条错误传播路径至少 1 例，断言异常类型**和**关键信息 |

参数组合爆炸时用 pairwise（两两组合）控制冗余——不许用"随机挑几个"糊弄。
断言必须精确：`assert result == expected`（具体值），禁 `assert result is not None` 充数。

## L2 集成测试

- 模块间调用链**真实执行**——内部逻辑（本项目代码）禁止 mock
- mock 白名单（仅外部依赖）：网络/HTTP、数据库、外部服务、时钟（now/sleep）、
  随机源、文件系统外部资源、环境变量
- 每个使用 mock 的测试必须注释：mock 了什么、为什么属白名单、真实失效会怎样
- 断言跨模块的数据流完整性（进什么、出什么、中间不变量）

## L3 E2E

- 至少 1 条从入口到出口的完整路径（CLI=真实 argv；API=真实请求；库=公开主入口）
- 断言最终可观测结果（输出/返回/副作用），不断言中间实现细节

## 属性/模糊测试（工具链支持时）

- 对可参数化输入给出**不变式**断言（例：解析再序列化 = 恒等；排序结果恒有序）
- 随机种子固定，失败可复现
- hypothesis (Python) / go native fuzz / fast-check (JS)

## 契约测试（单元有外部消费者时）

提供方与消费方各至少 1 例；破坏任一侧契约测试必须变红。

## 专项清单（逐项过——要么测，要么注明为何不适用）

| # | 专项 | 最少检查 |
|---|---|---|
| S1 | 空输入 | []、""、None、空文件、空流 |
| S2 | 极值 | 类型上下限、溢出行为 |
| S3 | 并发 | 竞态（共享可变状态）、重入、锁顺序死锁（适用时） |
| S4 | 资源泄漏 | fd/socket 关闭、临时文件清理、内存增长（长循环） |
| S5 | 幂等/重试 | 同输入重复调用、部分失败后重试 |
| S6 | 异常不吞 | 错误必达调用方或日志，禁止 except-pass |

## 反模式禁令（AST 扫描会抓，直接判 FAIL）

1. **禁无断言测试**——每个测试函数体内必须有实质断言
2. **禁恒真断言**——`assert True`、`assert x == x`、`expect(true)`
3. **禁吞异常**——`except: pass` / 空 catch 块（除非立即 re-raise 或断言）
4. **禁断言 mock 行为**——断言被测逻辑的真实计算结果，不是 mock 返回什么
5. **禁顺序依赖**——测试独立可跑（随机顺序不挂）
6. **禁共享可变 fixture**——跨测试可变状态
7. **禁测试内重实现被测逻辑**——expected 值来自手算/表驱动，不是复写算法
8. **禁改被测源码**——你只能新增测试文件（项目测试目录）

## 输出合约

- 文件放项目测试目录（遵循已有惯例：tests/、test/、__tests__、*_test.go 同目录）
- 返回**仅测试文件路径清单**——不要报告"测试已通过"之类的结论
  （独立验证器会执行并判定，你的自述无效且不被消费）
