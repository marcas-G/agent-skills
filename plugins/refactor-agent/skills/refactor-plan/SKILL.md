# E-6 规划器：批次计划

## 必守不变量

- INV-6.1 每批独立可回退：任一批回退后其余批次语义仍自洽。**跨批半成品依赖禁止**——一个提取的公共函数与其所有调用点必须在同一批，或调用点批次在其后且该批失败不破坏前批。
- INV-6.2 批次依赖无环。
- INV-6.3 高风险批（预期行为/测试断言例外）显式标注 `exception_expected=true` 并附例外声明模板（供决策④）。

## 风险分级（固定规则）

- 低：纯结构调整（移动/重命名/提取/内联），行为与断言零变化。
- 中：含删除（死代码/冗余分支）。
- 高：接口语义变化、测试断言需改、行为例外。

## 步骤

1. 输入：findings.md + 决策②选定的混乱点集合。
2. 按文件簇聚合混乱点（同文件/强相关文件的点合批）；批内文件数 ≤8 为宜。
3. 依赖排序：被依赖的提取/下沉先行；同文件多批按 P1→P3。
4. 每批标注风险级；高风险批附「例外声明：改什么行为/为什么/影响面」。
5. 无法独立分批（全耦合）→ **不产出违规计划**：输出「需多批联动」警告 + 建议缩小范围，交协调器回决策②。

## 产出 `docs/refactor/<round>/plan.md`

```markdown
# 批次计划
| 批次 | 目标混乱点（findings ID） | 文件 | 依赖 | 风险 | 例外声明 |
|---|---|---|---|---|---|
## 例外声明模板（exception_expected=true 的批次逐一批注）
- 批次 N：<行为/断言将怎么变>；<为什么非改不可>；<影响面>
```

完成后协调器执行：`log plan {"batches":[{"id":"1","files":[...],"risk":"low","exception_expected":false},...]}`，随后对每批 `baseline <批次id> <文件...>` 采集哨兵基线。
