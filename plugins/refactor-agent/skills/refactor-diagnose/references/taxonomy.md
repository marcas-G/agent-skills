# 四类混乱口径（单一来源，诊断与信号共用——DRV-4/INV-5.3）

> 口径外不存在第五类；归不进四类的发现标「待归类」，不硬塞。

## 1. 耦合
定义：改动一处被迫牵动别处的结构性纠缠。
检查模式：双向依赖/A↔B 互引；共享可变状态（全局变量/可变单例/穿透传参）；跨层直访（UI 摸存储/绕过领域层）；一个构造函数要凑齐五个协作者。
证据示例：`a.py import b 且 b.py import a`；`X 处函数签名含 3+ 个仅转发用的参数`。

## 2. 重复
定义：同一知识/逻辑的多份实现——改需求要改多处。
检查模式：结构相似的功能段（复制后微调）；同义配置散落多处；平行类型/平行函数（仅命名不同）。
证据示例：`foo_v2() 与 foo() 90% 相同`；`同一常量在 3 处硬编码`。

## 3. 职责不清
定义：模块/函数的边界模糊——名不副实或一职多能。
检查模式：一文件多职（攒一堆不相关函数）；名实不符（叫 Manager 实际只做一件事/或什么都做）；「utils/common/misc」黑洞；函数内嵌套 3 层以上异质关注点。
证据示例：`helpers.py 1200 行含 14 个不相关函数`。

## 4. 与理解不符
定义：代码行为与对齐后理解（alignment.md）冲突——认知债。
检查模式：实现了对齐中已废弃/否决的行为；SE 基线下的实现漂移（survey 已标出）；死路径（对齐理解里已无此需求但代码仍在）；与新理解矛盾的条件分支。
证据示例：`alignment R3 说已放弃导出功能，export.py 仍被路由引用`。
