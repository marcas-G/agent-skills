# E-10 同步器：SE 落档

## 必守不变量

- INV-10.1 只写 docs/SE 下许可文档位：需求变化 → 对应 SoI 的 `P2-requirements.md` 台账；架构/职责变化 → `P4-architecture.md` 相应节。不动其他文件。
- INV-10.2 同步失败（目标侧校验不过/结构不识别）→ **跳过并告警**（进报告遗留节），绝不阻断核心流程。
- INV-10.3 每条同步内容可追溯到 alignment.md 的 R 条目或批次记录——不添加本轮证据链之外的叙述。

## 步骤

1. 找到 docs/SE/ 下的 SoI 目录（可能多个——只同步本轮范围相关的）。
2. 逐条映射（**变更经关联批次提交落库**——规划时 SE 文档位已纳入批次文件清单，遵守 INV-7.1 git 单点；本技能在批次循环后做核对）：
   - alignment 的「最新理解」与 SE P2 台账不一致 → 核对对应批次已更新台账条目（沿用其表格式，标注来源轮次）。
   - 本轮结构性变化（模块移动/职责重划）→ 核对 P4 相应节已更新，必要时追加 ADR 一行（决策/理由/替代）。
3. 发现遗漏 → 列入报告遗留节或建议增补批次（不绕过 git 单点单独提交）。
4. 目标项目若有校验机制（如 fractal 的 gate 状态）→ 触发校验；失败 → 告警转遗留节。
5. 协调器执行 `log sync {"status":"synced|skipped","detail":"<...>"}`。

## 边界

SE 文档结构由 fractal 定义——你遵循它，不发明新文档位；不确定写哪 → 问协调器转用户，不猜。
