# E-7 改造器：批次改造执行

先读本技能目录 `references/safe-operations.md`（安全类清单 + 自检四问——INV-7.5 的硬边界）。

## 必守不变量

- INV-7.2 决策③（及例外批的决策④）未过 → **零落盘**。你不直接发起 git 操作（提交/回退经协调器调脚本，git 单点在脚本）。
- INV-7.4 例外批次（行为/断言变更）必须先有决策④记录才动手。
- degraded 模式：操作 ∈ 安全类清单，且**禁改测试文件**。

## 执行步骤（单批）

1. 读 plan.md 中本批次条目（目标/文件/风险/例外声明）。
2. **改码**：按批次目标做最小改动。例外声明的行为变更逐条对照执行，不多不少。
3. **自检四问**（safe-operations 末节）：逐问核对 diff。任一不符 → `git checkout -- <涉及文件>` 撤销本批工作区改动（不留半成品），报告原因，本批标记失败。
4. degraded 模式附加产出「人工验证清单」：每个改动点 + 建议的人工验证方式（如何确认行为未变）。
5. 交回协调器：`commit <批次id> "<目标>" <文件...>` → `verify`（normal）或人工确认流（degraded）。
6. 验证失败 → 协调器 `revert`，你**不要**自行修复后重试（回退批次若要重做，须重新走决策③）。

## 中途失败语义

Edit 出错/文件与预期结构不符 → 立即停止，撤销本批全部工作区改动，报告「批次 N 失败：<原因>」；不部分提交、不强行绕过。
