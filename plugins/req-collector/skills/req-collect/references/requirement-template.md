# requirement.md 模板（E4）

> 定稿产物结构。字段与顺序固定（INV-5），未决章节为必备章节（DRV-03），空则写"无"。

```markdown
# 需求：<标题>

| 元数据 | 值 |
|---|---|
| id | <目录名> |
| 版本 | v1.0 |
| 状态 | awaiting-confirmation →（用户确认后）finalized |
| 收集人 | <用户> |
| 需求方 | <如未提供写"未提供"> |
| 日期 | <YYYY-MM-DD> |

## 1 问题
<谁在什么情况下难以做什么——主体/场景/障碍>

## 2 场景
<主路径步骤，每步"谁做什么">

## 3 干系人
| 角色 | 关切 |
|---|---|

## 4 边界
**In Scope**
- <…>

**Out Scope**
- <…>

## 5 验收标准
- [ ] 给定 <条件>，应能 <可判定的结果>
- [ ] …

## 6 未决事项
< [UNRESOLVED]/[CONFLICT] 原样列出；无则写"无" >

## 7 附录：材料保真收录
< 材料中的约束/契约/判据/决策/术语等绑定内容**原样收录**（不改写、不删减），按主题分组，逐条标注来源文件；材料文件覆盖清单（已读 N/N）。材料极少时可写"无附录（材料已全部并入正文）" >

## 8 变更记录
- <从 state.md 平移>
```

## 生成规则

- 生成时元数据"状态"写 `awaiting-confirmation`；用户确认后与 state.md 一起改为 `finalized`（两次写同文件，INV-7 只锁 finalized 终态）。
- 草稿五要素 → 章节一一映射，不增删章节、不改顺序。
- [CONFLICT] 未裁决 → 双方原样进第 6 章，不选边（INV-6）。
- 章节映射不上（某要素既不齐备也无显式未决）→ 拒绝生成，回到收集循环。
- 结构变更 = 下游格式承诺变更：必须升插件版本号并在变更记录公告。
